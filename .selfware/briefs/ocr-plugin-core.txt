# TASK: ocr-plugin-core — opt-in, local-only OCR for images and scanned PDFs (GitHub #137, slice 1)

Scanned files are unsearchable today: TextExtractor returns None for .png/.jpg/.tif and for image-only PDFs. Add an OCR plugin interface, off by default, with tesseract as the first backend. Out of scope (separate briefs, why #137 stays open): macOS Vision and Windows.Media.Ocr backends, adding a scanned fixture to the eval corpus, document-type-aware extraction (passport, visa, medical, loan), sensitivity classification. Do not touch the MCP server.
1. src/sahara/ocr.py (new): a small `OcrBackend` Protocol (`name: str`, `available() -> bool`, `recognize(image_bytes: bytes) -> str`), a `TesseractBackend` using pytesseract and Pillow imported lazily (the `ocr` extra already exists in pyproject; `available()` is False when either the packages or the tesseract binary are missing, never raising), and `get_backend(name: str) -> OcrBackend | None` for names "auto" and "tesseract" ("auto" returns the first available backend or None). OCR must be local only: no network calls, no cloud OCR, state this in the module docstring. Never log recognised text; log only counts and file names at debug level.
2. src/sahara/config.py: add `ocr_enabled: bool = False` and `ocr_backend: str = "auto"` to SaharaConfig, following exactly how existing settings are declared, read, written and validated (and listed by `sahara config list`). Unknown backend names are rejected by `config set`.
3. src/sahara/search/search_engine.py TextExtractor: when OCR is enabled and a backend is available, (a) images with suffix .png .jpg .jpeg .tif .tiff .bmp .webp go through the backend instead of returning None, and (b) a PDF whose pypdf text is empty falls back to OCR of its embedded page images (pypdf `page.images`; do not add a PDF rendering dependency). With OCR disabled or unavailable, behaviour and return values are byte-for-byte what they are today. Cap work: at most 50 pages per PDF and skip any image larger than 20 MB, each counted as skipped. Keep a per-extractor counter object with ocr_done, ocr_skipped (too large, page cap, backend error, empty result) and ocr_unavailable_files, exposed so the indexer can read it. A backend exception on one file must not abort indexing.
4. src/sahara/cli.py: `sahara index` prints one extra summary line only when OCR is enabled: "OCR: N files read, M skipped" (and, if OCR is enabled but no backend is available, one warning line naming how to install tesseract and the `ocr` extra; never crash). Wire the extractor's counters to that line; make the smallest change that reaches the extractor the indexer actually uses.
5. Docs: SECURITY.md "What leaves your machine": add one short paragraph that OCR is off by default, runs locally with tesseract, sends nothing anywhere, and that recognised text goes into the same local index as any other text (so it is covered by every existing statement about the index). docs/COMMAND_REFERENCE.md: document `ocr_enabled`, `ocr_backend`, how to install the extra, and the summary line. CHANGELOG.md [Unreleased] "### Added" entry (#137). Extend tests/test_egress_docs.py with one short guard that `ocr_enabled` defaults to False and is documented in the section, comparing prose with whitespace collapsed like the file's other tests.

Tests in tests/test_ocr.py (new), using a fake backend object and no real tesseract: disabled by default returns None for a png and for an image-only pdf exactly as before; enabled with a fake backend returns its text for an image; an image-only PDF built in the test with Pillow (skip with pytest.importorskip("PIL")) falls back to OCR; a text PDF never calls the backend; oversize image and page cap are counted as skipped; a backend that raises on one file leaves the others indexed; get_backend("auto") is None when nothing is available; config rejects an unknown backend; the index summary line appears only when enabled; a test patching urllib.request.urlopen and socket.socket.connect to raise proves OCR makes no network call.
